# Design system

Pilovo 0.4.0 Preview opens on observed web activity. A row shows provider, non-sensitive local identity, evidence state and freshness. Focus and seen acknowledgment are separate actions. Unknown remains explicit when evidence expires or is inaccessible. Manual preparations and historical receipts retain their own provenance in separate views.

Unreleased source adds three activity details. Mark all as seen appears only when two or more rows need attention, uses the same lock and inline error as rows and confirms through a refreshed snapshot. A discreet hint shows the configured next-attention shortcut and is hidden when none is assigned. Working and attention rows, seen or not, add a short plain-text elapsed duration under the reason (“Working for 4 min”, “Réponse disponible depuis 2 min”) in 12 px muted metadata; it updates at minute boundaries without a live region, so it is never announced, and is absent for idle, unknown or unusable times.

Unreleased source also differentiates the toolbar badge. The count of unseen items to review sits on the color of the most urgent reason: red `#B42318` for a visible error, amber-brown `#8A4B08` for an input request, brand olive `#4B5D3A` for a response available. With nothing to review, observed work shows `…` on neutral gray `#5E5E5C`, signaling activity without a count. Text is white on every background, at a computed contrast of at least 4.5:1. Color is never the only carrier: a number versus an ellipsis separates review from work, and the icon's tooltip names the reason in text, in the app's language (“Pilovo — 3 à vérifier, dont 1 erreur visible · 1 en cours”, “Pilovo — 2 to review (responses available)”, or plain “Pilovo”). Seen, waiting and unknown sessions never light the badge; it carries counts and fixed reason words only.

Unreleased source also identifies sessions. The row heading is the worker's stable per-service number (“Claude · session 3”), never recomputed by the panel, or the user's name for the session followed by the provider in regular-weight muted text (“Revue contrat — Claude”); the name is isolated as bidirectional text and rendered as a text node only. A 12 px muted line under the heading gives the tab's 1-based position (“Onglet 4”, “Tab 4”) and adds “· autre fenêtre” / “· other window” when the tab is not in the window showing the panel; it is omitted when unknown, and the window part is omitted when the panel's window cannot be read. A compact 28 px pencil icon button (“Nommer cette session” / “Name this session”, described by the heading) follows the heading and is reachable by Tab. It turns the heading into a text field of the same height, whose visually hidden label names the session it renames and states the 40-character limit (“Nom de Claude · session 3 (40 caractères au plus, vide pour l’effacer)”); while it is open, the row keeps its heading, visually hidden, for screen readers. Enter or leaving the field applies the name, Escape cancels and returns focus to the button, an empty name clears it. Refused characters keep the field open, with its text and an announced error, whether the user pressed Enter or left the field; a failed change is announced in the row until its observation or name changes. The worker names only live observations, as for focus and seen: once a row's evidence has lapsed, or while access or the snapshot is uncertain, the button stays focusable but inert (`aria-disabled`, muted), so focus is never dropped; a live row without a recognized signal can still be named. The button and the field draw their focus ring inset, and stacked layouts never pull the heading line into the state line, so neither crosses the state or position line. Names, like other actions, appear from a refreshed snapshot. Rows follow their tab rather than the observation, so polling and navigation in the tab keep an open field, its text and focus. Coarse pointers get 44 px for the button and the field. Tab titles and URLs are never shown.

The physical scene: a professional reviews an agent's work next to a document in a daylight office, moving between a narrow Chrome side panel and a full browser tab. Light mode uses a white canvas to match that working surface; dark and system modes support evening review without changing semantics.

The color strategy is restrained. OKLCH tokens use a deep olive accent anchored at hue 110 (palette seed 118), near-black ink, neutral gray divisions and pure white surfaces. Accent is reserved for primary actions, selection and meaningful status. Dark mode has separately chosen text, border and action values. Semantic errors and waiting states use text and shape as well as color.

One system sans-serif family, 14 px normal content and controls, 12 px metadata, and a restrained 24/20/14 px heading hierarchy. Narrow navigation stays at 12 px. No display typography, upper-case eyebrow scaffolding, gradients, glass, ornamental metrics or repeating feature card grids.

Desktop is a navigation rail, an attention/task list, and a detail pane separated by fine 1 px rules. Below 760 px, navigation becomes a five-item top row and selection opens a single detail view. Back and Escape restore the task-row focus. Lists, forms and long receipts scroll within their own view; source text and URLs wrap without executing or injecting HTML.

Actions use a common border, 6 px radius and icon vocabulary. Lucide React supplies all interface icons under ISC; source names are written out and the generic terminal/code symbols do not pretend to be official brand logos. Destructive actions and mission reassociation use native modal dialogs. Their focus is trapped by the browser and restored on close; mutation failures are announced inside the active dialog.

State design:

- Empty production state explains how actual tasks arrive; there is no seeded demo in product code.
- Current response-ready attention requires witnessed work and stable ready evidence; it never verifies task success. Historical completion remains labeled as agent-reported.
- Missing metadata is explicit. Historical receipts derive duration from source timestamps and mark it partial for missing/uncertain evidence. Unreleased live elapsed durations restart when evidence is lost and are never stored.
- Prompts are collapsed and only appear if actually available under consent.
- Local SHA-256 check results show their scope, reference origin and time separately from overall verification and human review.
- No pause, stop, approval or notification control is exposed without support.

Transitions are 140–150 ms for controls and do not conceal initially visible content. Reduced motion removes transitions and the loading pulse. Keyboard navigation, visible focus, native form controls, explicit labels, live errors and 44 px coarse-pointer targets are part of the interface contract.

Historical 0.2.0 audit: initial supporting type was too small and dark rail states needed explicit color binding. Both were corrected. Browser tests then passed at 1365×900 and 360×800, including five axe WCAG AA scans. This does not validate the 0.4.0 activity screen. See `docs/ui-acceptance.md` and `docs/RELEASE.md` for scope and remaining manual checks.

## Pilovo identity

Public name: Pilovo. Signature: Keep your AI in view. Descriptor: AI activity for Chrome. Preview remains visible in promotional media. The native P monogram uses a round counter and activity point; six custom vector glyphs spell Pilovo. Ink `#20261F`, olive `#4B5D3A`, ivory `#F6F4EE` and limestone `#D9DDCF` define the media palette. See `docs/media/BRAND_GUIDELINES.md`.

Provider names remain plain text without implied endorsement. Abstract banner rows are editorial shapes; interface screenshots use synthetic local examples with explicit captions. No metrics, users or provider execution are fabricated. Internal database/native/protocol identifiers stay stable for compatibility.
