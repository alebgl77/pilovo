# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Pilovo is a Manifest V3 Chrome extension (Chrome 120+, 0.4.0 Preview) that observes ChatGPT/Claude web tabs the user explicitly authorizes and surfaces "working / response ready / attention / unknown" state in a side panel and toolbar badge. No backend, no model API, no telemetry. React 19 + TypeScript + Vite UI, esbuild for the worker and content script, IndexedDB (`idb`) for persistence, `zod` for every trust boundary.

Read `PRODUCT.md`, `docs/core-contract.md` and `DESIGN.md` before changing any user-facing behavior, permission, wording or UI. The contract is normative: permissions, evidence rules and lifetimes there are not suggestions.

## Commands

Node.js 22.12+ required.

```sh
npm ci
npm run typecheck            # tsc --noEmit (src, tests/core, vite.config.ts)
npm test                     # vitest: tests/core/**/*.test.ts + tests/ui/**/*.test.ts
npm run test:core            # vitest, core only
npx vitest run tests/core/activity-controller.test.ts   # single file
npx vitest run -t "name"     # single test by name
npm run test:publication     # node --test scripts/publication.test.mjs
npm run check:publication -- --tracked   # scans tracked files for leaks/allowlist/broken md links (CI runs this)
npm run build                # tsc + vite build (index.html, sidepanel.html) + scripts/build.mjs (background.js, observer.js) → dist/
npm run package:check        # validates release packaging without writing (needs dist/ from build)
npm run dev                  # UI preview only at 127.0.0.1:5173 (no real site observation)
```

CI (`.github/workflows/ci.yml`) runs, in order: `npm ci`, typecheck, test, test:publication, `check:publication -- --tracked`, build, package:check, package. Reproduce that locally before pushing.

`npm run package` creates immutable versioned ZIPs under `release/v<version>/` (per-version lock; refuses to overwrite). Only run it after reviewing the exact build. The script file is still named `scripts/package-briefoak.mjs` on purpose.

Playwright flows in `tests/ui/*-flows.mjs` and `tests/e2e/*.mjs` are standalone Node scripts (not vitest). UI flows target `HUB_TEST_URL` (default the dev server) and accept `CHROME_PATH`; they write to `tests/ui/results/`, `outputs/` and `docs/media/screenshots/`. Harnesses (`tests/ui/*-harness.html/tsx`) render UI with synthetic fixtures.

## Architecture

Three execution contexts communicate via `chrome.runtime` messages:

- **Service worker** — `src/background/index.ts`. Single RPC dispatcher on channel `hub.rpc`; requests are validated with `rpcSchema` (`src/shared/rpc.ts`) and only accepted from the extension's own `index.html`/`sidepanel.html` top frame. Mutating methods trigger a debounced `hub.changed` broadcast that the UI re-reads on. Channel `pilovo.observe` carries content-script hints only.
- **Content observer** — `src/content/observer.ts` + `evidence.ts`, bundled as an IIFE `observer.js` and dynamically registered (session-only, isolated world) by the worker after a per-provider host grant. There is no static `content_scripts` entry. Evidence uses fixed selectors and exact whitelisted accessibility tokens (EN/FR); never traverse or read transcript text.
- **UI** — `src/ui/` (rail + list + detail, collapses to single view below 760 px). It talks only to `HubClient` from `src/platform/client.ts`, which picks the extension RPC client when `chrome.runtime.id` exists, otherwise a local preview client backed by a separate IndexedDB (`agent-control-hub-preview-v1`) — that's what `npm run dev` uses.

Keyboard commands (`focus-next-attention`, suggested `Alt+Shift+J`; `acknowledge-all-attention`, unassigned) are handled by `chrome.commands.onCommand` in the worker and reuse `WebActivity.focus` (plus an attention-identity guard) and seen semantics; the no-candidate side-panel open must stay synchronous inside the command gesture (last focused window tracked via `windows.onFocusChanged`); the UI reads configured shortcuts with `chrome.commands.getAll` (`getShortcuts`). Manifest `commands` are not permissions.

Activity pipeline (`src/background/activity.ts`, `activity-reducer.ts`, `activity-injection.ts`, types in `src/shared/activity.ts`): `WebActivity` is written against an injected `ActivityAccess` interface (so tests drive it with fakes; `chromeActivityAccess` is the real adapter). Per-provider grants have serialized registration queues so revoke/regrant can't race. The worker issues leases (≤15 s, `ACTIVITY_TTL`) and pulls samples via `scripting`; hints only request a resample. Samples are checked for sender, origin, tab/top document, activation id, monotonic sequence and sample identity — late or stale messages are dropped. Activity state is in-memory only and discarded on worker restart. `stateSince` (monotonic, same clock as `validUntil`/`attention.raisedAt`) marks when the current state or attention identity began; the reducer keeps it across same-state samples and the ready debounce. The panel derives ephemeral working/attention durations from it (`src/ui/activityModel.ts`) and re-renders at minute boundaries only while one is shown; never persist or export them. The toolbar badge is a pure rule in `src/background/activity-badge.ts` over live observations (unacknowledged attention count on the most urgent reason's color, else `…` for working, else empty; title with counts only) painted by `WebActivity` through `ActivityAccess.badge` with no call when unchanged; its title follows `settings.language` (set via `setLanguage` at startup and after `updateSettings`, re-read from storage when that call fails), not `chrome.i18n`. The expiry watchdog rounds its delay up and `expire()` re-arms it when nothing has expired yet: the monotonic clock is fractional and timers truncate their delay. Tab-level identity lives in `WebActivity.sessions` and `WebActivity.labels`, beside the records, and `snapshot()` adds it to each observation (so the badge never sees it): per-provider `sessionNumber` (smallest free at first observation, kept across record replacement, released on tab close, revoke or the tab leaving that provider), `tabIndex` (Chrome `Tab.index`, refreshed on samples and by `reindex()` on tab create/remove/move/attach/detach) and the user's `label` (keyed by tab and tagged with its provider: it outlives the tab leaving that provider, is shown only on that provider, and is cleared on tab close/replace, that provider's revoke or worker restart; set through the strict `labelWebActivity` RPC on live observations only, like focus/seen; worker memory only: never persisted, exported, badged or notified). Write bidi/control characters in source as escapes: `check:publication` refuses raw bidi controls. The panel never computes numbers itself (named rows still show theirs, `Label — Claude · session 3`, the only link to OS notifications), renders labels as text nodes and keys rows by provider + tab so navigation keeps an open rename field. Optional automatic seen (`settings.autoAcknowledgeSeconds`: exactly 0 = off by default, 5, 15 or 30, strict in both the RPC and repository schemas; settings stored by older versions lack it, so every repository read merges the stored record over `DEFAULT_SETTINGS` without migration) is applied by `setAutoAcknowledge` beside `setLanguage`, under the same ordered settings guard in `index.ts`. `WebActivity` tracks the viewed tab (the active tab of Chrome's focused window) through `viewChanged(windowId?)`, wired from `windows.onFocusChanged` (negative = `WINDOW_ID_NONE`) and tab replace, and `tabViewChanged(tabId, windowId)`, wired from `tabs.onActivated` and tab attach/detach, which leaves a running dwell alone when the event touches neither the viewed tab nor the viewed window, plus `ActivityAccess.viewing()` (`windows.getLastFocused` + `tabs.query({ active, windowId })`, IDs and flags only, never called while `autoAcknowledgeSeconds` is 0 and `notifyProviders` is empty; notifications query it once per candidate). A single dwell timer, re-evaluated in `changed()`, is bound to one record identity, attention identity and grant; at its deadline it re-queries Chrome, re-checks everything synchronously and only then calls `acknowledge()`. Seen stays a local acknowledgment, never verification. Optional OS notifications (`settings.notifyProviders`: distinct `WebProvider`s, default `[]`, same strict RPC/repository schemas and merge; applied by `setNotifyProviders` under the same ordered guard) live in `WebActivity` with fixed FR/EN text and opaque IDs from `src/background/activity-notifications.ts`, through `ActivityAccess.canNotify/showNotification/clearNotification/shownNotifications` (not `notify`, which broadcasts `hub.changed`): one notification per newly raised attention identity, only for a listed provider, with the permission, when the tab is not viewed (`viewing()`), re-checked synchronously after those async checks; never for attention raised before enabling, nor for the same reason re-raised in the same tab with only unknown/expired evidence in between. Content is provider name, reason and `sessionNumber` only, never the label/title/URL. At most one per tab and 16 live; `syncNotices()` (in `changed()`) clears it when its attention ends, but only lapses it when the evidence merely lapses (unknown other than navigation, or expired): for `NOTICE_GRACE` (35 s) the same reason raised again in that tab rebinds the notice to that new identity (same ID, no Chrome call), matching the repeat guard; otherwise it is cleared. A click (`notificationClicked`) clears it and runs `focus()` on the identity it currently stands for, first resampling a lapsed tab (`until()`, ≤ `NOTICE_RESAMPLE`), never seen. `chrome.notifications` is absent until granted and refuses calls once removed: `index.ts` adds its listeners at startup or on `permissions.onAdded` (which also sweeps leftovers via `notificationsGranted()`), `updateSettings` awaits `noticesSettled()` (≤ 2 s) when `notifyProviders` changes so the page's later `permissions.remove` cannot overtake the clears, and `permissions.onRemoved` only forgets them (`notificationsRevoked()`); each worker life clears `pilovo:` leftovers. The `pilovo-activity` alarm starts observation only after `ready` (settings applied). The Settings checkboxes call `requestNotificationPermission` synchronously in the change event and show a service as on only while `hasNotificationPermission` confirms it. "Response ready" requires witnessed working → stable ready signal after debounce; anything absent/ambiguous/expired is `unknown`.

Persistence (`src/domain/repository.ts`, `HubRepository`): IndexedDB `agent-control-hub-v1`, schema version 4. Web preparations carry an integer `revision`; updates need `expectedRevision` and fail with `preparation.conflict` on stale writes. Prompt retention is per-record opt-in, off by default. Export is schema 2. Legacy native-agent receipts/missions/reviews keep their own provenance and are never converted into observed activity.

Errors cross the RPC boundary as string codes (`HubError` / `errorCode` in `src/shared/errors.ts`); the UI localizes codes via `src/ui/i18n.ts` and `public/_locales/{en,fr}`.

## Invariants to preserve

- Required permissions are exactly `storage`, `sidePanel`, `alarms`, `scripting`; optional hosts exactly `https://claude.ai/*` and `https://chatgpt.com/*`, requested individually; the only optional API permission is exactly `notifications` (opt-in OS notifications, requested only from a UI click, never by the worker, never required). No `tabs`, `nativeMessaging`, other optional permissions, broad hosts, telemetry or automatic prompt submission without a separately reviewed scope proposal.
- Keep separate: tab presence, human declarations (`prepared` / `sent_by_user` / `completed_by_user`), and observed UI evidence (`observed_ui`). Focus/copy/open/"seen" never imply submission, approval or task success.
- Legacy identifiers stay stable for compatibility even though the product was renamed (Briefoak → Pilovo, originally "agent control hub"): `agent-control-hub-v1`, `hub.rpc`, `hub.changed`, `NATIVE_HOST`, `HubRepository`, `package-briefoak.mjs`.
- `companion/`, `tests/companion/`, native e2e scripts and `src/shared/protocol.ts` (native event schema) are historical reference: not bundled, not part of the default product. Native/bridge RPC methods intentionally throw `bridge.unavailable` / `permission.denied`.
- Never commit real prompts, exports, profiles, credentials or personal paths; screenshots and fixtures must be synthetic and labeled as such. `check:publication` enforces a file allowlist and leak patterns — any new root-level file or top-level directory must be added to `rootFiles`/`rootDirectories` in `scripts/publication-lib.mjs` or CI fails (it also lands in the source ZIP).
- Docs must not claim store approval, coverage, user counts, reliability numbers or provider endorsement.
- Bug fixes come with a regression test.
